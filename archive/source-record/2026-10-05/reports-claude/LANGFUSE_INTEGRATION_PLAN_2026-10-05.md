# Langfuse integration plan (2026-10-05)

Scope: trace every agent call (gateway, agent-core, engine, support-platform) as one trace per end-to-end story. Research only: no data sent to Langfuse, no env values read (key names only: LANGFUSE_SECRET_KEY, LANGFUSE_PUBLIC_KEY, LANGFUSE_BASE_URL). Sources: langfuse.com docs (OTel endpoint, best-practices, token-and-cost, scores, experiments-via-OTel, advanced-features, pricing), github.com/langfuse/skills, and our code at the paths below.

## 1. How Langfuse works (10 bullets)
1. Data model: **trace** (one unit of work) holds **observations** (span, generation, event, plus agent/tool/chain/retriever/guardrail/evaluator/embedding types); traces group into **sessions**; also user id, tags, metadata, environment, release, version.
2. Ingest: OTLP/HTTP at `{LANGFUSE_BASE_URL}/api/public/otel` (`/v1/traces`), Basic auth `base64(pk:sk)`, header `x-langfuse-ingestion-version: 4` (otherwise up to 10 min delay). HTTP protobuf or JSON only: **no gRPC**; traces only (no metrics/logs).
2b. Mapping: `langfuse.*` attrs win over `gen_ai.*`. A span with a model attr becomes a generation. `gen_ai.usage.input_tokens/output_tokens` are read. Input/output come from `langfuse.observation.input/output` or `gen_ai.prompt/completion`. Unmapped attrs land in `metadata.attributes.*` and are NOT filterable; use `langfuse.trace.metadata.<k>` / `langfuse.observation.metadata.<k>`.
3. Trace-level fields (`langfuse.session.id`/`session.id`, `langfuse.user.id`/`user.id`, `langfuse.release`, `langfuse.trace.tags`, `langfuse.trace.name`, metadata) must sit on **every span**: copy via OTel Baggage + BaggageSpanProcessor, or the SDK's `propagate_attributes()`. Tags are immutable (set at creation); later labels are **scores**.
4. Cross-service linkage is plain W3C `traceparent`; Langfuse needs a root span in the batch.
5. SDKs: Python and JS/TS (OTel-native, v4; `@observe`, `propagate_attributes`, `mask_otel_spans`, `sample_rate`, `should_export_span`, `run_experiment`). **Go and Rust: no SDK**, use plain OTel.
6. Cost: ingested usage/cost wins; otherwise the generation `model` is matched (regex `matchPattern`) to a model definition with per-unit prices. Custom models via UI or `POST /api/public/models`; user definitions beat built-ins; computed at ingestion only (not retroactive).
7. Scores (NUMERIC / CATEGORICAL / BOOLEAN / TEXT) attach to trace, observation, session or dataset run via `POST /api/public/scores`. Langfuse-managed LLM-as-judge evaluators target observations by name/type and read input/output/metadata.
8. Datasets + experiments: items (input, expected output) run through a task, one trace per item; compare runs side by side. Direct-OTel path: baggage `langfuse.experiment.{id,name,dataset.id}` + root attrs `langfuse.experiment.item.{id,root_observation_id,expected_output}`.
9. Limits (Cloud Hobby): 50k units/mo (unit = trace + observation + score), 30-day retention, tracing 1,000 req/min, public API 30 req/min, 1 annotation queue. Core 100k units + $8/100k, 90 d; Pro 3 y. Regions: EU `cloud`, US `us.cloud`, JP `jp.cloud`, HIPAA; keys are region-bound.
10. Skill best practices (langfuse/skills): fetch docs fresh, never from memory; use latest SDKs; name observations verb-first and stable (no ids, no model names); type each step (generation, tool, agent); one generation per model call (never wrap a loop); capture model, tokens, thinking; set trace input/output explicitly (not raw args); mask PII; add session_id/user_id/tags only where code shows the concept; **self-audit**: send a trace, fetch it back, compare to the best-practices page, fix, repeat; flush before exit; name scores after the observed signal (`draft_edited`, not `quality`); feedback scores via application code or an evaluator.

## 2. Findings in our code
- **llm-gateway**: tracing is already OTel. `internal/telemetry/telemetry.go:21-40` installs a TraceContext+Baggage propagator and an OTLP/HTTP exporter only if `OTEL_EXPORTER_OTLP_(TRACES_)ENDPOINT` is set (so **Wave A is env-only**). `httpapi.go:183` extracts inbound `traceparent`; `gateway.go:148` starts span `chat <model>` (client kind) with `gen_ai.operation.name/provider.name/request.model/response.model`, `gen_ai.usage.input_tokens/output_tokens`, finish reasons. `internal/jev/jev.go:149` has span `jev systemone`. Gaps for Langfuse: labels are mapped to `run_id`, `turn_id`, `session_id`, `agentcore.release`, `agentcore.agent` (`gateway/telemetry.go:9-17`), which Langfuse does not recognise as session/release/tags; **no input/output** (policy comment `telemetry.go:19`); no cost.
- **agent-core**: `agent_telemetry/setup.py:29-51` takes `endpoint` + `headers`, private provider (never global, F3). Contrary to the brief, the `serve` path **does** read OTEL_* from the injected env (`composition/observability.py:80-101`, validated; header var at :93; `setup_observability` :231). So transport is env-only. Spans: `invoke_agent`, `agentcore.decide`, `agentcore.rule`, `execute_tool`, `chat`, `agentcore.transfer` (`spans.py:31-38`); attributes pass a **closed allowlist** (`spans.py:46-62`) so any `langfuse.*` attr is dropped; `set_content` (`spans.py:157`, off by default, `agentcore.content.*`) is not a Langfuse key. `api/tracing.py:39` starts `agentcore.api.request` **without extracting inbound traceparent** (no `extract(` anywhere), so platform and agent-core do not join. Outbound already injects `traceparent` to gateway (`adapters/llm/http_gateway.py:86`), tool service and platform, and sends labels (`:92-105`).
- **support-platform backend**: no OpenTelemetry dependency (`backend/pyproject.toml`), one shared `httpx.AsyncClient` to agent-core (`bootstrap/container.py:406`), headers built in `infrastructure/ai/http_runtime.py:45-49` (Authorization, X-On-Behalf-Of). **Frontend**: React/TS feature `api.ts` modules (`frontend/src/features/*/api.ts`), no tracing.
- **engine** (`worktrees/improvement-engine-claude-cons`): all model calls go through `ModelPort` (`seams/crates/engine/src/models/mod.rs:104`), `Recording::call` (`:194`) sees every call; stages call it at `seams/crates/reasoning/src/pipeline.rs:127` (scout), `:145` (verifier), `:164` (builder). Real gateway client `models/llm_gateway.rs:83-112` (labels only `agent=pulso-<role>` at :93; headers :98; **no traceparent**). The HTTP client is hand-rolled `std::net` with **no TLS** (`llm_gateway.rs:53-55`, `core-client/src/http.rs:26`): the engine cannot post to Langfuse Cloud directly. No tracing/OTel crates. Branch `claude/o11y1-run-trace-bridge` exists locally but has **no commits beyond main (f43c67f4)**; `scripts/o11y` does not exist yet.

## 3. Recommended architecture
- **Single OTLP path, no Langfuse SDK in services.** Gateway (Go) and agent-core (private provider) cannot use the Python/JS SDK anyway. Everything emits standard OTel with `langfuse.*` attributes.
- **One local OTel Collector** (contrib image, in `scripts/dev-stack`) as the only egress: receives OTLP/HTTP plain on `:4318` (fits the engine's no-TLS client), holds the Langfuse Basic-auth secret in one place, applies a `transform` processor for masking (Bearer tokens, `sk-`/`pk-`, api keys), exports `otlphttp` with `x-langfuse-ingestion-version: 4`, `batch` + `memory_limiter`. Services point to it with no credentials. Wave A may skip the collector (direct env) as a smoke test.
- **Engine bridge**: a small Python script (`scripts/o11y/`, the lane `claude/o11y1-run-trace-bridge`) reads debug-api run events and emits OTLP spans with **deterministic ids** plus scores. Python gives TLS and the Langfuse SDK for scores/datasets; Rust only adds a `traceparent` header and labels.
- **Trace = one story.** Engine trace `improvement-story` (root span), `trace_id = sha256(run_id)[0..16]`, `span_id = hash(run_id, stage, attempt)` (resume after kill and re-sends are idempotent). Children: `ingest`, `scout` (agent) > `generate` (generation, from gateway), `verifier`, `builder`, `arm-run`, `verdict`, `human-decision` (events). `session.id = run_id`; later re-runs and human follow-ups of the same finding share the session. Platform trace `support-turn` (one per customer message/analyst question), `session.id = case id` (or conversation id); agent-core `invoke_agent` nests under it; gateway `chat` nests under agent-core.
- **Propagation**: `traceparent` everywhere (already: agent-core->gateway/tools/platform). Add: platform->agent-core, engine->gateway, and agent-core must **extract** inbound. Session/release/tags via Baggage + BaggageSpanProcessor (no PII, pseudonymous ids only).
- **Attributes**: tags (low cardinality, immutable): `agent:<id>`, `release:<id>`, `locale:<xx>`, `case-type:<x>`, `stage:<scout|verifier|builder>`. High-cardinality values (finding key, case id, run id, prompt id) go to **metadata** (`langfuse.trace.metadata.finding_key`), per best practices. `langfuse.environment` = `dev|staging|prod|experiment`. `langfuse.release` = git sha / agent release id. Observation names stable and verb-first: `scout`, `verify-opportunity`, `build-proposal`, `chat`, `decide`. Do not put model names in span names (gateway's `chat <model>` should become `chat` with model as an attribute).

## 4. Per component (change, owner, effort, risk)
**Gateway (Go; human team via user). Wave A.**
- A0, no code: env `OTEL_EXPORTER_OTLP_ENDPOINT=<LANGFUSE_BASE_URL>/api/public/otel` (Go appends `/v1/traces`), `OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic%20<b64 pk:sk>,x-langfuse-ingestion-version=4` (percent-encode the space), `OTEL_SERVICE_NAME=llm-gateway`, `OTEL_RESOURCE_ATTRIBUTES=deployment.environment.name=dev`. Result: one trace per call, tokens + model + finish reason, no content. Effort 0.5 h. Risk: keys in gateway env; use the collector later.
- A1, additive PR (about 40 lines): (a) in `labelAttributes` also emit `langfuse.session.id`, `langfuse.release`, `langfuse.trace.metadata.agent`, `langfuse.trace.metadata.run_id`; (b) opt-in `LLM_GATEWAY_CAPTURE_CONTENT=true` sets `langfuse.observation.input` (system prompt + inputs) and `langfuse.observation.output` (output object) and `langfuse.observation.model.parameters`; (c) set `langfuse.observation.type=generation`, and `langfuse.observation.cost_details={"total":..}` when the request profile carries price; (d) register `baggagecopy` span processor. PR text: "Additive, off by default. Maps existing labels to Langfuse trace attributes and adds opt-in content capture, so traces from callers who authorise it show prompt and answer. Default behaviour unchanged." Effort 0.5-1 day. Risk: closed-attribute policy (`telemetry.go:19`) is a team decision.
**agent-core (Python; human team via user). Wave C.**
- C0, env only: `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`, `OTEL_SERVICE_NAME=agent-core` (verify the header validator at `observability.py:93` accepts `Basic <b64>`).
- C1, PR 1 (3 lines, `api/tracing.py:39`): `ctx = extract(request.headers)` passed as `context=ctx` to `start_as_current_span`. Without it no cross-service trace.
- C2, PR 2 (allowlist `spans.py:46-62`): add `langfuse.session.id`, `langfuse.trace.name`, `langfuse.trace.tags`, `langfuse.release`, `langfuse.environment`, `langfuse.observation.type`, `langfuse.observation.input/output`, `langfuse.trace.metadata.*`; derive them from the existing `bind(session_id, release, agent, locale)`; type `invoke_agent` as `agent`, `execute_tool` as `tool`, and mark agent-core's own `chat` span `span` (the gateway span is the generation; avoids double generations and double cost). Content only via existing `capture_content` flag, mapped to `langfuse.observation.input/output` (authorised by the user, but the team owns the flag). Effort 1-2 days. Risk: allowlist is an "interface change" in their M11 spec; update spec in the same PR.
**support-platform (Python/FastAPI + SPA; human team via user). Wave D.**
- Backend: add `opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http`, `opentelemetry-instrumentation-fastapi`, `-httpx` (traceparent injection on the agent-core client, `container.py:406`), `opentelemetry-processor-baggage`; init at startup; root span `support-turn` with `langfuse.session.id=<case/conversation id>`, `langfuse.user.id=<pseudonymous analyst/customer id>`, tags `locale`, `case-type`; exclude DB/HTTP noise spans. Exporter to the collector (or Langfuse directly). Effort 2-3 days.
- Feedback: the existing handoff label (`api/schemas/cases.py:572`, useful/incomplete/unnecessary) and thumbs become scores via backend `POST /api/public/scores` (trace id from the stored response `trace_id`, which agent-core already returns).
- SPA: **no Langfuse keys in the browser.** The SPA sends a `traceparent` (new trace id per user action) and `X-Session-Id` on API calls and posts feedback to the backend; backend CORS must allow `traceparent`, `baggage`. Effort 1 day. Optionally `@opentelemetry/sdk-trace-web` later for UI latency.
**Engine (ours). Wave B.**
1. `llm_gateway.rs:93-98`: add `traceparent` header and labels `run_id`, `session_id`, `release`, `agent` (add an optional trace context to `ModelRequest`, `mod.rs:77`). 0.5 day.
2. `scripts/o11y/trace_bridge.py` (lane o11y1): tail debug-api events -> OTLP spans (deterministic ids, stage spans, `scout/verifier/builder` agent observations with input/output), push to the collector; flush at exit. 2-3 days.
3. Optional later: native Rust spans (`opentelemetry-otlp` over a TLS-capable client or a localhost collector). Not needed now. Risk: bridge lag vs real timing; mitigated by event timestamps.

## 5. Scores, datasets, experiments, judges
- **Scores** (name after the signal; BOOLEAN/CATEGORICAL/NUMERIC; attach to the story's root observation, idempotent `id`): `battery_pass` (bool) and `battery_score` (num) per agent test run; `rubric_total` + per-criterion `rubric_<c>` (num) from the rubric judge; `human_decision` (cat: approved/rejected/changes_requested) from the human review; `outcome_verdict` (cat: pass/fail/inconclusive) from the arm-run verdict; `handoff_label` and `thumb` from the platform. Rate: public API is 30 req/min on Hobby, so batch and throttle in the bridge.
- **Datasets**: one dataset per agent test battery (item = input, `expected_output`, metadata locale/case-type); one per artifact kind for rubric calibration.
- **Experiments**: run the battery per model profile (flash, pro, glm) as experiments `battery-<date>-<model>` on the same dataset via `run_experiment` (Python SDK v4) with the gateway profile as the task; `langfuse.environment=experiment`; compare in Langfuse. Direct-OTel attributes (section 1.8) if the runner stays outside Python.
- **Langfuse-managed LLM-as-judge**: evaluators on observation name `scout|verifier|builder` and generation type, mapping input/output/metadata (expected output, rubric) to the judge prompt; calibrate against human labels first (skill reference judge-calibration). Needs an LLM connection key configured in Langfuse (a provider key the user owns); cost and rate apply. Keep our own deterministic rubric scores as ground truth and use the managed judge as a second opinion.
- **Prompt management**: later; link `langfuse.prompt.name/version` on generations once agent-core prompts are versioned there. Not in scope now.

## 6. Cost registration and privacy
- Register models once (`POST /api/public/models`, prices per token USD): `xiaomi/mimo-v2.6-flash` -> `(?i)^xiaomi/mimo-v2\.6-flash$`, `xiaomi/mimo-v2.6-pro`, `z-ai/glm-5.3-flash`, plus the engine default `deepseek/deepseek-v4.1-flash` (price per Mtok / 1e6). Usage keys `input`, `output` match gateway tokens. Prices must come from you (engine defaults 0.15/2.4 per Mtok are only for deepseek). Alternative: gateway sends cost (A1c).
- You authorised all content. Still recommend: mask Bearer/`sk-`/`pk-`/api keys/JWTs in the collector `transform` processor (Python `mask_otel_spans` in the bridge); never put secrets or PII in Baggage (it crosses to third parties); pseudonymous user ids; do not log Authorization or `X-On-Behalf-Of`; keep Langfuse keys server-side only. agent-core rule 6 (no full-view PII to logs/events) is the team's; send content only from the views they already treat as audit-safe. Retention is 30 days on Hobby; export what you need to keep.
- Volume (Hobby 50k units/mo): story about 15 units (1 trace + ~12 observations + scores) -> ~3,000 stories/mo; support turn about 8-10 units -> ~5,000 turns/mo; a battery of 200 items x 3 models is about 9k-12k units. Sample prod later (`sample_rate`, whole-trace) or upgrade; keep 100% in dev.

## 7. Rollout and Definition of Done
- **Wave A (gateway, env only, 0.5 day)**: DoD: a gateway call from the engine shows in Langfuse as a `generation` with model, tokens, finish reason, latency; fetched back via API and checked against the best-practices page; no secret in span attrs. Then the A1 PR requested.
- **Wave B (engine, 3-4 days)**: DoD: one run yields one trace `improvement-story` with stage spans and 3 nested gateway generations (scout, verifier, builder) linked by traceparent; session = run id; tags/metadata present on every span; resume after kill does not duplicate spans; scores `outcome_verdict`, `rubric_total` present; collector holds the only key.
- **Wave C (agent-core, needs C1+C2 merged, 2 days)**: DoD: a turn shows `invoke_agent` > `decide` > `chat` generation (from gateway), tools typed `tool`; session, release, agent tags on all spans; trace id equals the `trace_id` returned in `TurnResult`; no double cost.
- **Wave D (platform, 3-4 days)**: DoD: one analyst question yields one trace from `support-turn` through agent-core to the gateway; SPA feedback becomes a score on that trace; evaluators and a dashboard (cost per agent/model, failures by `error.type`) exist.
- Each wave closes with the skill's self-audit loop and a note in the Nexus checkpoint outbox.
